# Deploying Gauntlet

One compose file, `deploy/docker-compose.prod.yml`, runs everything on a single host: api, worker, web (Next.js production build), Postgres with pgvector, Redis, SeaweedFS (S3-compatible object storage, Apache-2.0), the Damn Vulnerable Agent targets, and Caddy for HTTPS. All images build for linux/amd64 and linux/arm64, so Oracle Ampere, Hetzner CAX and ordinary x86 VPSs all work.

## Quick start (any Ubuntu or Debian VPS, 4 GB RAM or more)

```sh
git clone <repo-url> /opt/gauntlet && cd /opt/gauntlet
sudo ./deploy/bootstrap.sh --domain gauntlet.example.com      # omit --domain for a plain-HTTP IP demo
GAUNTLET_API_KEY=<key printed at the end> BASE_URL=https://gauntlet.example.com scripts/demo_smoke.sh
```

`bootstrap.sh` installs Docker if missing, adds a 2 GB swap file on small hosts, creates `deploy/.env.prod` (mode 600) with generated secrets, builds, starts, migrates, loads the demo data, and prints the admin API key once. Re-running it updates the code and re-applies the stack without changing existing secrets. Open the site and paste the admin key on the login page.

Without a domain the site is plain HTTP on the server IP; the script sets `GAUNTLET_INSECURE_COOKIE=1` so the login cookie works. Do not use IP mode for anything but a short demo: the API key travels in clear text.

Costs: hosting is 0 on Oracle Always Free and about 4 to 8 EUR a month on Hetzner. Model spend is separate, only happens when `OPENROUTER_API_KEY` is set, and is capped (below). The seeded demo, the smoke test, and the policy pages use no model calls.

## Variables (`deploy/.env.prod`, see `.env.prod.example` for every one)

| Variable | Purpose |
|---|---|
| `COMPOSE_PROFILES` | `caddy` (proxy and HTTPS), `dva` (vulnerable demo agents). Drop `caddy` under Coolify/Dokploy. |
| `DOMAIN` | Public DNS name. Empty means plain HTTP on port 80. |
| `POSTGRES_PASSWORD`, `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD` | Generated by `bootstrap.sh`. The `MINIO_ROOT_*` names are kept for compatibility; they are the S3 access key and secret for SeaweedFS. |
| `GAUNTLET_SECRET_KEY` | Fernet key for stored secrets. Back it up; losing it loses them. |
| `GAUNTLET_ADMIN_API_KEY` | Admin key (`gk_...`), created at every start if missing. |
| `OPENROUTER_API_KEY` | Enables live model calls. Empty keeps the stack model-free. |
| `GAUNTLET_MAX_RUN_BUDGET_USD_MICROS` | Per-run cap; requests above it are clamped. 5000000 is $5. |
| `GAUNTLET_DAILY_BUDGET_USD` | Rolling 24 hour cap over all runs and campaigns; over it the API answers 429. 0 disables. |
| `GAUNTLET_ATTACKS_DISABLED` | `true` rejects every attack run at the API. |

`GAUNTLET_ENV` is fixed to `prod` in the compose file: no dev API key, no `/v1/dev/seed`, no `/openapi.json`. CORS is not needed: the browser only talks to the web app, which proxies to the API server-side (`GAUNTLET_API_URL=http://api:8000` inside the network). Caddy also exposes `/v1/*` and `/healthz` for SDK, CLI and ingest clients; they authenticate with API keys.

## Setting the model key and spend caps

1. Create a key at openrouter.ai and set a monthly spend limit on the key there. This is the hard stop that does not depend on Gauntlet.
2. Put it in `deploy/.env.prod` as `OPENROUTER_API_KEY=...`, or export it before `sudo -E ./deploy/bootstrap.sh`.
3. Choose caps: `GAUNTLET_MAX_RUN_BUDGET_USD_MICROS` (per run) and `GAUNTLET_DAILY_BUDGET_USD` (per day; finished runs count what they actually spent, queued and running ones their budget, and the total plus the new run's budget must fit). Apply with `docker compose -p gauntlet -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod up -d`.

## Oracle Cloud Always Free (Ampere A1, ARM64)

1. Create an instance: Ubuntu 22.04 or 24.04, shape `VM.Standard.A1.Flex`, 2 OCPU and 12 GB RAM is plenty (the free allowance is 4 OCPU and 24 GB in total). Add your SSH key. Note the public IP.
2. Open ports in the VCN: Networking, Virtual Cloud Networks, your VCN, the subnet's Security List, Add Ingress Rules: source `0.0.0.0/0`, TCP, destination ports `80` and `443`; add a second rule for UDP `443` (HTTP/3, optional).
3. Open ports on the instance too. Oracle's Ubuntu images carry an iptables rule that rejects everything except SSH, so the VCN rule alone is not enough. `bootstrap.sh --open-ports` inserts ACCEPT rules for 80 and 443 and saves them if `iptables-persistent` is installed (`sudo apt install iptables-persistent`). By hand: `sudo iptables -I INPUT -p tcp --dport 80 -j ACCEPT`, the same for 443, then `sudo netfilter-persistent save`.
4. Point a DNS A record at the public IP (needed for HTTPS), then SSH in and run the quick start with `--open-ports`.
5. If you get "Out of host capacity" creating an A1 instance, retry later or pick another availability domain; it is a free-tier capacity limit.

## Hetzner (CAX ARM or CX x86)

1. Create a server: CAX21 (4 vCPU ARM, 8 GB, about 7 EUR a month) or CX32 (x86). Ubuntu 24.04, your SSH key.
2. Hetzner Cloud has no host firewall by default. If you attach a Cloud Firewall allow inbound TCP 22, 80, 443 and UDP 443.
3. Add the DNS A record, SSH in, run the quick start. No `--open-ports` needed.

## Any other VPS

Ubuntu or Debian, 4 GB RAM minimum (8 GB comfortable), 20 GB disk, ports 80 and 443 reachable. Run the quick start. For a non-Debian host install Docker with the compose plugin yourself, copy `.env.prod.example` to `.env.prod`, fill in the values (`openssl rand -hex 24` for passwords, `openssl rand -base64 32 | tr '+/' '-_'` for `GAUNTLET_SECRET_KEY`, `gk_` plus `openssl rand -hex 16` for the admin key), and run:

```sh
docker compose -p gauntlet -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod up -d --build --wait
docker compose -p gauntlet -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod exec api python -m gauntlet_server.demo seed
```

## Coolify or Dokploy

1. New resource, Docker Compose, from the Git repository; set the compose file to `deploy/docker-compose.prod.yml` and the base directory to the repository root (the build contexts are `..` relative to the compose file).
2. Environment: set `POSTGRES_PASSWORD`, `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`, `GAUNTLET_SECRET_KEY`, `GAUNTLET_ADMIN_API_KEY`, the spend caps, and optionally `OPENROUTER_API_KEY`. Set `COMPOSE_PROFILES=dva` (no `caddy`), so the platform's own proxy does TLS.
3. Domain: attach your domain to the `web` service on port 3000. For SDK or CLI clients add a second domain, or a path rule for `/v1`, on the `api` service port 8000. Leave `GAUNTLET_INSECURE_COOKIE=0` because the platform serves HTTPS.
4. Deploy. After it is healthy, run the seed once from the platform's terminal on the `api` container: `python -m gauntlet_server.demo seed`.
5. Nothing in the file publishes host ports, so it does not collide with the platform's proxy.

## Operations

- Update: `git pull && sudo ./deploy/bootstrap.sh` (migrations run on every start).
- Logs: `docker compose -p gauntlet -f deploy/docker-compose.prod.yml logs -f api worker`.
- Scale workers: `... up -d --scale worker=2` (watch memory).
- Backup: `deploy/backup.sh -d /var/backups/gauntlet -k 7` writes a timestamped tarball of a `pg_dump` and the SeaweedFS data directory and keeps the newest 7. Cron: `17 3 * * * /opt/gauntlet/deploy/backup.sh -d /var/backups/gauntlet -k 14`. Copy the directory off the host. Back up `deploy/.env.prod` separately and securely; `GAUNTLET_SECRET_KEY` is in it.
- Memory limits (total about 4.3 GB at the limits): postgres 768m, redis 160m, seaweedfs 384m, api 768m, worker 1g, web 512m, caddy 96m, each DVA 192m.
- Verify any time: `scripts/demo_smoke.sh` (no model spend).

## Security checklist

- [ ] `GAUNTLET_ENV=prod` (fixed in the compose file); `/v1/dev/seed` and `/openapi.json` return 404 (the smoke test checks).
- [ ] No public signup exists. Access is by API key only; keep the admin key private and create narrower keys for others.
- [ ] HTTPS via `DOMAIN`; IP mode only for short demos.
- [ ] `deploy/.env.prod` is mode 600 and not in git; the key shown once by `bootstrap.sh` is stored in a password manager.
- [ ] Spend: a limit on the OpenRouter key itself, plus `GAUNTLET_MAX_RUN_BUDGET_USD_MICROS` and `GAUNTLET_DAILY_BUDGET_USD`.
- [ ] Kill switch known: Security page, kill switch card, stops runs in flight; `GAUNTLET_ATTACKS_DISABLED=true` rejects new attack runs.
- [ ] The DVA services are intentionally vulnerable. They publish no ports and are reachable only inside the compose network. Do not publish them. Drop the `dva` profile when not demoing.
- [ ] Attack runs against hosts other than the DVA require DNS or HTTP ownership verification; `GAUNTLET_ALLOW_PRIVATE_TARGETS` stays `false`.
- [ ] Postgres, Redis and SeaweedFS publish no ports. Only Caddy (80 and 443) is exposed.
- [ ] Backups run and one restore has been tried.

## Migrating from MinIO

MinIO is archived and its images are no longer pullable, so the stack now uses SeaweedFS (`chrislusf/seaweedfs:4.55`, Apache-2.0, amd64 and arm64). Env var names (`MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`, `S3_*`) are unchanged. The storage volume is new (`s3data`), so an existing deployment must copy its bucket data across:

1. Before upgrading, run the old `deploy/backup.sh`. The tarball holds the bucket objects under `minio/`.
2. Upgrade and start the stack; the empty `gauntlet` bucket is created automatically.
3. Extract the tarball, `docker cp <dir>/minio/cassettes "$(docker compose -p gauntlet ps -q seaweedfs)":/tmp/cassettes`, then `docker compose -p gauntlet exec seaweedfs weed filer.copy /tmp/cassettes http://localhost:8888/buckets/gauntlet/`.

New backups contain the SeaweedFS data directory under `s3/` instead of `minio/`.
